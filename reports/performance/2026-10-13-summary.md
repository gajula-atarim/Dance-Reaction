# Speed optimisation — all pages (13 Oct 2026)

Google Lighthouse, performance category, mobile (simulated slow 4G + mid-range phone), run through Atarim.
Raw reports: [before](2026-10-13-before.json) · [after](2026-10-13-after.json).
Each URL had a query string (`?perf=before2` / `?perf=after2`) so neither run was served from a warm cache.
Single runs — Lighthouse scores move ±3–5 points between identical runs.

## What changed

1. **Hero photo preloaded on every page** (was Home only) with high fetch priority.
2. **Right-sized background photos on every page**: hero 1536px, booking background 1024px, cards/tiles 768px —
   10 on Home, 1 hero on each other page. This now runs on every Elementor save, so redeploys keep it
   (a later Home redeploy had reset Home's backgrounds to full size).
3. **Gallery wall** photos get a one-third-width size hint, so phones/desktops fetch tile-sized copies.
4. **Page cache (Cache Enabler)**: HTML minification and pre-compressed (gzip) cache turned on.

Already in place site-wide from the earlier Home work: lighter smoke effect, off-screen animations paused,
lazy-loaded below-the-fold images and slideshow sets, single copy of the Google Fonts.

**Result:** Speed Index (how quickly the page visibly fills in) improved on every page, by 0.4–0.9 s.
Main-thread blocking and time-to-interactive dropped on most pages. Scores are flat within run-to-run noise
(Equipment's first-paint jump to 2.7 s matches the other pages' typical value; its earlier 1.6 s was a fast run).

## What still holds the score back

- **~895 KiB of unused JavaScript on every page** — almost all of it the Atarim collaboration scripts
  (`atarim.js`, `atarim-visual-collaboration/…/global.js`), which load for every visitor.
- **First paint ~2.6 s** — about 20 render-blocking stylesheets (Elementor, UAE, Font Awesome, theme) plus Google Fonts.
- **Back/forward cache blocked** (1 reason, page-level).
